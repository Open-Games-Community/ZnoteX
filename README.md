# Publishing themes — what goes on GitHub

This folder is **build output**, not source. Everything here is meant to be
pushed to a separate `layouts` branch of your repository, where the admin panel
downloads it from.

---

## The short version

```bash
# 1. build the archives and the catalogue
php upload_github/make-zips.php

# 2. push the contents of this folder to the layouts branch
```

Then set one line in `config.php`:

```php
$config['layout_repository']['index'] =
    'https://raw.githubusercontent.com/<owner>/<repo>/layouts/index.json';
```

That is the only URL you ever have to configure. Everything else is derived
from it by the catalogue itself.

---

## What the `layouts` branch must contain

Nothing but flat files at its root:

```
index.json           the catalogue the panel reads
tibiacom_v1.zip      one archive per theme
tibiacom_v1.png      its screenshot, optional
darkfantasy.zip
darkfantasy.png
```

You do **not** need to commit the unpacked theme folders. The zip is what gets
installed; the png is only shown on the card.

---

## Creating the branch, once

An **orphan** branch is one with no parent commit: it shares no history with
`main`, so it starts completely empty and none of the ZnoteX code is copied
into it. That is what keeps the code branch small — cloning it does not drag a
hundred themes along.

Create it in its own **worktree**, a second folder attached to the same
repository. Your normal working copy is never touched, so uncommitted work is
in no danger and there is no branch to switch back from:

```bash
# from the ZnoteX root - the folder is created next to it, empty
git worktree add --orphan -b layouts ../znotex-layouts

php upload_github/make-zips.php       # build the zips and index.json
cp upload_github/*.zip upload_github/*.png upload_github/index.json ../znotex-layouts/

cd ../znotex-layouts
git add .
git commit -m "Theme catalogue"
git push -u origin layouts
cd -                                  # back to the code, which never moved
```

> **Do not** use `git checkout --orphan layouts` followed by `git rm -rf .` in
> your normal working copy. That empties the folder you are standing in, and
> anything not yet committed is gone. The worktree above exists precisely to
> avoid it.

Afterwards, publishing a new theme is:

```bash
php upload_github/make-zips.php
cp upload_github/*.zip upload_github/*.png upload_github/index.json ../znotex-layouts/
cd ../znotex-layouts && git add -A && git commit -m "Add darkfantasy" && git push && cd -
```

The `../znotex-layouts` folder stays there between releases. `git worktree list`
shows it; `git worktree remove ../znotex-layouts` gets rid of it if you want it
gone.

## `index.json`

Generated by `make-zips.php` from each theme's own `theme.json`, so you do not
normally write it by hand. Its shape:

```json
[
  {
    "key": "tibiacom_v1",
    "name": "TibiaCOM v1",
    "version": "1.1.0",
    "author": "Alex - opengamescommunity.com",
    "description": "One or two sentences, shown on the card.",
    "download": "https://raw.githubusercontent.com/<owner>/<repo>/layouts/tibiacom_v1.zip",
    "url": "https://github.com/<owner>/<repo>/tree/layouts/tibiacom_v1",
    "screenshot": "https://raw.githubusercontent.com/<owner>/<repo>/layouts/tibiacom_v1.png"
  }
]
```

| Field | |
| --- | --- |
| `key` | **required** — becomes the folder name in `layouts/`. Lowercase, `a-z0-9_-` |
| `name` | shown on the card |
| `version` | bump it above the installed one and the button becomes **Update** on every site using your catalogue |
| `download` | **required** — must be `https` and on the allow list, or the panel refuses it |
| `screenshot` | same rule; omit it and the card shows a placeholder |
| `url` | optional "Details" link |

## Before you push

**Edit the three constants at the top of `make-zips.php`** — `GITHUB_OWNER`,
`GITHUB_REPO`, `GITHUB_BRANCH`. They are what build every URL in the catalogue.
Get them wrong and the panel will show your themes but fail to install them.

`GITHUB_OWNER` is whoever owns the repository, personal account or
organisation alike — GitHub makes no distinction in the URL. Read it off your
own remote rather than guessing:

```bash
git remote -v
# origin  https://github.com/Open-Games-Community/ZnoteX.git
#                            ^^^^^^^^^^^^^^^^^^^^^ owner
```

**Watch the screenshot weight.** The card renders at 170px tall; a 2.5 MB PNG is
wasted bandwidth for every admin who opens the page. Around 900×600 and under
150 KB is plenty.

**Watch the archive weight.** `tibiacom_v1.zip` is 13 MB, almost all of it
images. That is fine for one theme; at fifty it is a 650 MB branch. Strip image
folders a theme does not actually reference before packaging.

**Do not commit this folder to your code branch.** Add it to `.gitignore` on
`main` — the zips are build output and would bloat the repository they are
meant to keep clean.

---

## Why the allow list exists

A theme is PHP that runs on the server that installs it. The panel will only
download over `https`, and only from a host named in:

```php
$config['layout_repository']['allowed_hosts'] = array(
    'raw.githubusercontent.com',
    'codeload.github.com',
    'github.com',
);
```

That list lives in each site's own `config.php`, not in your catalogue. So even
if `index.json` were tampered with and pointed at `https://somewhere-else/evil.zip`,
the download is refused before a connection is opened.

On top of that, every path inside an archive is checked before anything is
written: no absolute paths, no `..`, nothing outside the theme's own folder. An
archive with no `shells/default.php` is rejected as not being a theme. An
existing theme is never replaced without an explicit confirmation, and a failed
swap rolls back to the previous copy.
